===INPUT===
Taux d'acceptation quotidien de nos autorisations CB sur 30 jours, part des décisions prises en secours, et les 5 codes réponse de refus les plus fréquents par jour. PostgreSQL.

autorisation(id, horodatage timestamptz, jeton_pan, montant_centimes, devise, mcc, canal 'proximite'|'vad'|'dab', code_reponse char(2), secours boolean)
code_reponse '00' = accord.
===OUTPUT===
### Question reformulée
Pour chacun des **30 derniers jours**, la part des autorisations accordées (`00`), la part décidée **en secours**, et les **5 codes de refus** les plus fréquents avec leur part des refus.

- **Grain :** une ligne par jour (synthèse), une ligne par jour et code (top 5).
- **Période :** les 30 jours complets avant aujourd'hui, en heure de Paris.
- **Hypothèse :** les annulations ne sont pas dans cette table *(à confirmer)*.

### Requête

taux_acceptation.sql
```sql
WITH a AS (
  SELECT (horodatage AT TIME ZONE 'Europe/Paris')::date AS jour, code_reponse, secours
  FROM autorisation
  WHERE horodatage >= (current_date - 30) AND horodatage < current_date
)
SELECT jour,
       COUNT(*)                                                                   AS autorisations,
       ROUND(100.0 * COUNT(*) FILTER (WHERE code_reponse = '00') / COUNT(*), 2)    AS taux_acceptation_pct,
       ROUND(100.0 * COUNT(*) FILTER (WHERE secours) / COUNT(*), 2)               AS secours_pct
FROM a
GROUP BY jour
ORDER BY jour;
```

Top 5 des codes de refus par jour :

```sql
WITH refus AS (
  SELECT (horodatage AT TIME ZONE 'Europe/Paris')::date AS jour, code_reponse, COUNT(*) AS n
  FROM autorisation
  WHERE horodatage >= (current_date - 30) AND horodatage < current_date
    AND code_reponse <> '00'
  GROUP BY 1, 2
),
classes AS (
  SELECT jour, code_reponse, n,
         ROUND(100.0 * n / SUM(n) OVER (PARTITION BY jour), 1)                    AS part_des_refus_pct,
         ROW_NUMBER() OVER (PARTITION BY jour ORDER BY n DESC, code_reponse)      AS rang
  FROM refus
)
SELECT jour, rang, code_reponse, n, part_des_refus_pct
FROM classes
WHERE rang <= 5
ORDER BY jour, rang;
```

### Fonctionnement
1. L'horodatage est converti en heure de Paris avant de prendre la date : un paiement à 0h30 compte bien sur le bon jour.
2. `COUNT(*) FILTER (WHERE …)` compte accords et décisions de secours en un seul passage.
3. **classes** calcule la part de chaque code dans les refus du jour et les classe ; en cas d'égalité, le code départage pour un résultat stable.

### Lecture des codes CB
| Code | Signification | À regarder |
|---|---|---|
| 51 | Provision insuffisante | Niveau normal, suit les jours de paie |
| 05 | Ne pas honorer | Trop générique : quelles règles le renvoient ? |
| 59 | Suspicion de fraude | Évolution des règles de fraude, attaques |
| 41 / 43 | Carte perdue / volée | Monte après une campagne d'opposition |
| 91 | Émetteur de cartes inaccessible | Problèmes du serveur ; comparer avec `secours_pct` |

### Contrôles
- **Totaux :** la somme de `autorisations` sur 30 jours = `COUNT(*)` sur la même période.
- **Parts :** par jour, la somme de `part_des_refus_pct` sur tous les codes (sans le filtre top 5) vaut 100.
- **Contrôle manuel :** un jour, un code, comptés à la main.
