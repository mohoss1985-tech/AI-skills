# 03 · Skill tools: what the best tools do, and what each V2 tool needs

Scope: 17 skills (API testing is covered in a separate research file). For each one: the reference tools, the 3–4 minimum inputs, the interactive core, exports, and a 60-second card-payments demo (Visa EN / CB FR). The stack constraints come from GOAL.md: Python stdlib server, vanilla JS, SQLite, a static GitHub Pages demo, and AI through `kit.py`. That means every tool core has to run client-side in plain JS. AI is an assistant button, not a dependency.

### What the best tools share

1. **A live artefact, not a prose answer.** bpmn-js renders and edits real BPMN XML. sql.js runs real queries. Productboard's matrix is dragged by hand. Voiceflow lets you test from any block.
2. **Structure first, prose last.** ChatPRD's main value is its templates plus a critique ("coaching") pass against common gaps. Example Mapping is four card types and a 30-minute timebox.
3. **Computed signals.** WSJF = (BV + TC + RR/OE) / job size, scored on modified Fibonacci (1, 2, 3, 5, 8, 13, 20). Impact heatmaps use a 0–3 scale. KB freshness is age bucket × owner.
4. **Import-ready exports.** Xray's CSV formats differ between Cloud and Server/DC. Jira CSV, `.feature` and `.bpmn` files open in the target tool on the first try.

## Decisions for Analyst Kit V2

General rules (apply to every tool):

- **G1. One shell, three panes.** Each tool has (a) a minimal-input header with at most 4 fields and "Advanced ▾" for the rest of the V1 questions, (b) an interactive core, (c) exports with an "Ask Claude" side action. The core works with no AI and no network, so it also works in the static demo.
- **G2. "Load sample" button on every tool.** Two samples, Visa (EN) and CB (FR), each runnable in 60 s with a 3-step coach mark.
- **G3. Shared JS primitives.** Build these once: an editable grid (sort, cell types, CSV in/out), a score cell (Fibonacci / 0–3 / 1–5), a 2x2 / bubble chart, a node-graph canvas, a Markdown preview. Most tools are combinations of them.
- **G4. Vendored libraries only.** Commit bpmn-js (modeler bundle) and sql.js (`sql-wasm.js` + `.wasm`) into `static/vendor/` so the tools work offline and on Pages. No other heavy dependencies.
- **G5. AI role is draft, critique or judge.** The tool owns the data. The AI fills it in, reviews it, or scores it, and every AI output lands in the grid or canvas so the user can edit it.

Per skill:

1. **PRD → structured editor + completeness checker.** Inputs: problem, evidence, user, success metric. Core: sectioned editor with G/R/M IDs and a live trace meter (every requirement maps to a goal, every goal has a metric). AI: draft sections, then a ChatPRD-style critique listing gaps. Export: MD/DOCX, epic CSV. Demo: Visa 3DS frictionless-rate PRD.
2. **User stories → Example Mapping board + Gherkin editor.** Inputs: role, goal, rules, tool. Core: 4-colour card board, with green cards compiled into Scenarios under Gherkin `Rule:`. Lint INVEST, and flag open red cards as "not ready". AI: propose examples and SPIDR splits. Export: `.feature`, Jira/Linear CSV. Demo: card-limit decline rule.
3. **Functional specs → rules table + field dictionary.** Inputs: feature, actors, systems, known rules. Core: RG grid (ID, condition, action, error message, source) plus a fields grid. AI: write the SFD prose around the tables. Export: DOCX/MD, plus RG CSV that feeds tools 7 and 8. Demo: CB FR PAN declaration.
4. **Processes → bpmn-js modeler.** Inputs: process, trigger, lanes, happy end. Core: an editable BPMN canvas with a lint panel. AI: text → BPMN XML (validate before rendering, fall back to a template on parse error). Export: `.bpmn`, SVG. Demo: Visa 13.1 chargeback.
5. **SQL → in-browser SQLite playground.** Inputs: question, tables, period, grain. Core: editor + Run on a bundled card-payments sample DB (sql.js in the browser, Python `sqlite3` locally), result grid, auto checks (row count, NULL keys, duplicate grain). AI: question → SQL + plain-language explanation + dialect translation. Export: `.sql`, CSV. Demo: approval rate by MCC.
6. **Backlog → WSJF calculator + PI capacity planner.** Inputs: items with BV/TC/RR/size, velocity, sprints, deadlines. Core: live-sorted WSJF grid, a sprint capacity bar with a cut line, a ROAM board. Reuse the existing V1 WSJF script logic in JS. AI: suggest scores and write PI objectives. Export: Jira CSV. Demo: 8 payment features.
7. **UAT → execution tracker + go/no-go gauge.** Inputs: scope, planned cases, testers, exit criteria. Core: Pass/Fail/Blocked grid, defect quick-add, burn-up, a gauge computed from the exit criteria. Save to SQLite; the static demo uses localStorage. AI: triage defects and draft the PV de recette. Export: PV DOCX/MD, defects CSV. Demo: day-3 no-go.
8. **Xray → test case editor + import validator.** Inputs: story keys, Cloud/DC, test type, project key. Core: steps grid, coverage matrix, a validator per flavour (column rules differ between Cloud and DC). AI: stories/AC → tests. Export: Xray CSV (both flavours), `.feature`. Demo: 2 stories → 6 tests → valid Cloud CSV.
9. **Data mapping → two-column mapper.** Inputs: source fields, target fields, key, PII flag. Core: click-to-connect lines (MapForce-lite), rule per line, code-value table, DQ chips. Unmapped required targets block "Export". AI: auto-match names and suggest transforms. Export: mapping CSV/XLSX, reconciliation SQL (runnable in tool 5). Demo: ISO 8583 → JSON with PAN masking.
10. **Workshops → agenda builder + live capture.** Inputs: topic, decision, attendees, duration. Core: timeboxed agenda that must sum to the duration, a live timer, tagged note capture, dot-vote on options. AI: questions per topic, and notes → compte-rendu. Export: MD/DOCX report, actions CSV. Demo: refund-rules workshop.
11. **Gap & impact → impact heatmap + traceability grid.** Inputs: change, deadline/source, as-is, affected teams/systems. Core: click-to-score 0–3 heatmap, with owner and size per non-zero cell, and an article → requirement grid. AI: propose the impacted cells with a reason, and draft the sponsor summary. Export: CSV/XLSX, MD, PNG. Demo: SCA exemption change.
12. **Stakeholders → power/interest grid + RACI matrix + decision memo.** Inputs: stakeholders, message, audience/date, options. Core: drag grid, RACI cells with a one-A rule, an options table (pros, cons, cost) that drives the memo. AI: draft the memo and steering update in the audience's tone. Export: CSV, MD. Demo: tokenisation launch.
13. **Knowledge base → audit grid + coverage map.** Inputs: content list, top questions, writers/week. Core: computed freshness and ownership flags, question → doc coverage, gap backlog fitted to capacity. AI: detect duplicates/contradictions and rewrite to the retrieval standard. Export: backlog CSV. Demo: Visa FAQ audit.
14. **Conversational journeys → flow canvas + test chat.** Inputs: need, "solved", hand-off rule. Core: small node graph (shared G3 canvas, not bpmn-js) with a test panel that walks it, starting from any node (like Voiceflow). Hand-off and fallback nodes are mandatory. AI: utterances, response copy, stories with conversational AC. Export: flow JSON, MD stories, Mermaid. Demo: CB FR refund status.
15. **RAG evaluation → golden-set scorer.** Inputs: golden Q + expected answer, actual answers + contexts, thresholds. Core: grid with offline checks (required facts present, citation present, refusal expected vs given) and an optional AI-judge faithfulness/relevance column (Ragas/DeepEval definitions: claims supported / total claims). Threshold bar gives the release verdict. Export: results CSV, promptfoo YAML for CI. Demo: invented 180-day window fails.
16. **AI risk → classification wizard + risk register.** Inputs: data seen, actions, users, hosting. Core: AI Act tier wizard (every result labelled "to confirm with legal"; NIST Govern/Map/Measure/Manage tags on controls), a likelihood × impact register, red-team cases. AI: propose risks, guardrails and red-team prompts. Export: register CSV, checklist MD, red-team CSV for Xray. Demo: servicing bot with PAN access.
17. **AI use cases → weighted scorer + bubble chart + roadmap.** Inputs: use cases + volume, capacity per quarter, excluded regulated topics. Core: editable weights (default value 35 / feasibility 25 / alignment 20 / inverse risk 20), live bubble chart, Now/Next/Later fitted to capacity, regulated items excluded with a visible reason. AI: score suggestions with a one-line rationale, and outcome goals. Export: CSV, roadmap MD. Demo: 8 Visa support intents.
18. **API testing** is covered by the separate API-tester research. Reuse its request/assertion model so the RAG scorer (15) and Xray (8) can import its saved test cases.
